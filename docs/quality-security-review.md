### Positive observations (facts)

- Access checks live in one place (`ProjectAccess`) and every use case calls it first; non-members get `404`, members without the role `403`, as EC-05 and US-04/US-08 require.
- A task is always loaded through its project (`TaskLookup.require(projectId, taskId)`), which closes the usual IDOR path of using another project's id.
- The author of a comment and the current user come from the token, not from the request body; unknown request fields are rejected (`fail-on-unknown-properties`, verified `400`).
- Probes with `curl` as Ana (V6): `GET /projects/not-a-uuid` → `404`; `?status=WRONG` → `400` with a field error; extra field `projectId` in the task body → `400`; POST without body → `400` (title required); `Content-Type: text/plain` → `415`; `dueDate` `31-12-2026` → `400`; title `<script>alert(1)</script>` → `201`, stored as text (EC-08).
